## 1. Executive Summary

PeteMart is a hyperlocal digital commerce marketplace targeting **5,000+ traditional merchants** across **21 historic Pete markets** in Old Bangalore. The platform supports **three interaction modes**:  
- **Mode A (Direct Purchase)**: Customers buy directly from merchants with 4% B2C commission (1.5% B2B).  
- **Mode B (WhatsApp Enquiry)**: Zero-commission discovery via WhatsApp deep-links.  
- **Mode C (Visit Store)**: Offline purchase with store location guidance; no commission.  

The platform includes tiered subscription plans (Starter ₹499/mo, Growth ₹999/mo, Premium ₹2,499/mo) and operates on a **zone-based hyperlocal delivery network** with multi-store order consolidation.

This feasibility study evaluates the technical viability of building, deploying, scaling, maintaining, and securing PeteMart, and recommends a high-performance UI stack and API-first implementation strategy.

## 2. Technical Feasibility Study

### 2.1 Building the Platform

#### 2.1.1 Core Requirements
- Support 5,000+ merchants across 21 markets.  
- Enable three interaction modes with distinct workflows.  
- Implement multi-store order consolidation with dynamic delivery fees.  
- Integrate with payment gateway (Razorpay) and WhatsApp API.  
- Provide merchant onboarding, subscription billing, and analytics.  

#### 2.1.2 Architecture Pattern
- **API-First, Monorepo (Next.js)**: All services exposed via Next.js API Routes.  
- **Micro-architecture**: Logical separation of concerns (frontend, backend, data, AI).  
- **Event-Driven**: Supabase webhooks + pgmq for asynchronous processing.  

#### 2.1.3 Key Components
- **Frontend**: Next.js 14 (React 18) with App Router, Server Components, and Server Actions.  
- **Mobile**: React Native (Expo) with TypeScript, React Navigation, and Expo Camera for AR try-on.  
- **Backend**: Next.js API Routes (serverless functions) with middleware for rate limiting.  
- **Database**: PostgreSQL (Supabase) with row-level security and real-time subscriptions.  
- **Auth**: Supabase Auth (email OTP, social login).  
- **Queue**: pgmq (PostgreSQL-based message queue) for async jobs (order processing, notifications).  
- **Cache**: SWR (stale-while-revalidate) + Supabase Realtime for client/server caching.  
- **AI**: DeepSeek API (pay-per-token) for product recommendations, virtual try-on, and dynamic pricing.
